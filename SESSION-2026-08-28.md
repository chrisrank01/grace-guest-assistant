### publish.py

Flags: `--deploy`, `--min-quiet-minutes N`, `--quiet`.
RESULT statuses: `deployed`, `nochange`, `would_change`, `debounced`,
`quiescence_check_failed`.
Exit codes: **2** = validation refused, nothing written. **3** = quiescence check
failed.

Validator refuses: broken references, self-reference, orphaned questions (BFS both
directions, derived from the Page column), malformed link hrefs,
`watch-online`-as-follow-up, empty answers, duplicate slugs, **duplicate IDs**,
**shippable-status-with-empty-slug**, **a destination cell yielding zero links**.
Input is normalised first (trim + casefold on Status/Page/Slug, ASCII `->` accepted).

### auto-publish.yml — verified surface

Inputs: `force_publish`, `simulate` (`none` / `failure` / `deploy_ping`).
Steps: checkout → setup-python → deps → wrangler → SIMULATE failure → SIMULATE
deploy ping → write key → Publish → commit → **Notify on failure** → **Notify on
deploy** → remove key.

`force_publish` sets `--min-quiet-minutes 0` and is **dispatch-only by
construction** — `inputs` is empty on a schedule event, so the clock can never skip
the debounce.

## SESSION LOG — 2026-08-28

**Batch Sheet write.** With the service account temporarily promoted to Editor,
`tools/sheet_write.py` wrote 77 cells: 11 harvested link destinations (CARE-01..04,
CON-01, NXT-05, KID-06, ORL-01, GIV-04, GIV-05, NXT-02), 18 draft answers with
buttons and notes for the FUTURE rows, nine Source/Notes banking entries, the FLAGS
D1 resolution, a READ ME rule line, and a CHANGE LOG row. Every cell was guarded:
links had to match an expected-old value, answer cells had to be empty, notes were
appended never overwritten. The first attempt died at cell 60 on a Sheets API 429 —
**60 write requests per minute per user** — and the guards made the re-run safe,
correctly reporting 25 skips that were all evidence of prior success. The script was
then rebuilt to batch per worksheet: 77 cells in 4 requests.

**The answer/question mismatch.** Eight of the 18 draft answers landed on the wrong
rows — the draft document had been written against *reconstructed* question
phrasings, not the Sheet's actual ones. IDs matched; the questions behind them
didn't. `tools/sheet_remap.py` fixed it with a snapshot-first design so the two
three-cycles (GRP-F1←F2←F3←F1, ABT likewise) could not clobber their own sources,
plus an abort-if-changed re-check immediately before writing. Same pass added all 18
F-row slugs with a column-wide uniqueness assertion. **Lesson: draft against the
Sheet's real questions, never against a reconstruction of them.**

**Validation and normalization.** Strict dropdowns went onto ANSWERS `Status` and
`Page` and PLACEMENT `URL path`, with a warning-only fence on `Slug`. `Show / Hide`
was deliberately deferred, then normalised: six compound values like
`SHOW (when SRV-F written)` became `SHOW` with the condition appended to the `Why`
column, `OPTIONAL` became `HIDE`, and `[SHOW, HIDE]` was applied. A publish dry run
proved the normalization changed nothing that ships — the six affected rows are all
outside `PILOT_ROUTES`.

**The scheduler that never fired.** The auto-publish workflow's GitHub `schedule:`
trigger fired **zero** times in 16 hours — nine consecutive missed ticks. Every
misconfiguration was ruled out from the machine: `state=active`, file on the default
branch, Actions enabled, public non-fork repo, valid cron. Nothing was wrong;
GitHub's hosted scheduler had simply dropped them. Separately, run #2 showed red
although its deploy had succeeded — a human push landed mid-run and the runner's
commit was rejected non-fast-forward. Both were fixed: a Cloudflare Worker
(`worker-clock`) now owns the cadence, and the commit step gained
`git pull --rebase` plus one retry.

**Notifications proven.** `simulate=failure` fired the high-priority tier. The first
`simulate=deploy_ping` **silently did nothing** — the notify condition matched only
`steps.publish.outputs.result_line`, and the simulation skips that step, so it
printed a convincing RESULT line while testing nothing. Fixed so the simulation sets
the same output and the notify step reads either source; re-ran, and the success
tier fired.

**publish.py hardening.** Four new fail-loud gates (duplicate ID,
shippable-with-empty-slug, destination-yields-zero-links, duplicate slug), input
normalization, and ASCII `->` leniency. Each gate was sabotage-tested to prove it
fires, with a clean control run. One regression was caught in the process:
casefolding the page map broke the BFS expected-set lookup, which the clean dry run
surfaced immediately.

**Design tokens.** Extracted by parsing the CSS out of `public/grace-assistant.js` —
every colour with its usage sites, the three font stacks, radii, spacing, press
states, transitions, the scroll-fade gradient. Notable finding: the 19
`rgba(41,46,56,…)` / `rgba(255,84,0,…)` values are hardcoded, **not derived from the
`NAVY`/`ORANGE` constants**, so a rebrand would leave them at the old hue.

**Analytics baseline (reported by Chris, not machine-verified).** MonsterInsights:
~18,000 sessions/month, ~90% new users, ~26s average session. This is the opening
argument for 9/15 — a high-traffic site where almost everyone is a first-time
visitor who leaves in under half a minute.

**Permission revert, with a receipt.** The service account was returned to Viewer
and the closure was *proven*, not assumed: a no-op write through the SA returned
`APIError: [403]: The caller does not have permission` while reads continued to
work.

## STANDING RULES

Each of these was bought with an incident. They are not style preferences.

1. **A green check is not a deploy.** `debounced` exits 0 and shows green. Read the
   `RESULT status=` line. Rough tell: ~20s run declined, ~40–50s deployed.
2. **Verify deploys twice, cache-busted.** Cloudflare's edge served stale content
   three times this project, twice producing a false "deploy failed".
3. **Control-grep before blaming the tool.** A "missing" string was twice a redirect
   swallowing a query parameter, and once a `serve` 301 body.
4. **Every gate needs a positive assertion *and* a control.** Sabotage-test it. The
   first BFS check was structurally incapable of failing; so was the first
   deploy-ping simulation.
5. **Batch Sheet edits, then hands off.** The 30-minute debounce means a trickle of
   edits keeps deferring the publish. Edit in a block, then leave it alone.
6. **Keys never go near the repo without a proven ignore.** Canary-test the rule
   *before* the real secret exists: `touch secrets/canary.json`,
   `git check-ignore -v`, confirm, delete.
7. **The Editor window opens rarely and closes with a failed-write receipt.** Grant
   → batch → verify → revert → prove the revert with a 403.
